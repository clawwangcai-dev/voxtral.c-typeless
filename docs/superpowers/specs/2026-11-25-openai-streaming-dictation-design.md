# OpenAI 流式听写（API 模式）设计

日期：2026-11-25　状态：第 2 版，已确认（已按 Codex 和 Antigravity 的对抗审核修改）

使用者决定的有四项：方案 A；听写时做静音检测；停顿前后允许上传一小段真实环境音；
单次听写上限默认 10 分钟。其余是我的决定。

## 目的

听写的高频场景是一句话里混用中文、英文、德文，本地 Voxtral 模型处理不好。
给听写程序（`voxtral_daemon.m` / `Voxtral.app`）加一个 API 模式，用 OpenAI 的流式转写，
边说边出字，延迟尽量低。

## 目标、不做、反目标

**目标**

- 按 ⌥Space 后，文字在说话的同时打进当前窗口，三种语言各自保留原文。
- 听写时做静音检测，长时间不说话时不上传（使用者要求）。
- 不引入新依赖（只用系统自带的 Foundation 网络库）。
- 本地模式保留；没有主动开启 API 模式的人，行为和现在完全一样。

**不做**

- 不改命令行 `./voxtral`。
- 不做设置界面，不做运行中切换本地 / API。
- 不接其他厂商。

**反目标**（出现任何一条都算失败）

- 已经打进窗口的字被退格重打。
- 使用者没有主动开启，音频却被上传。
- 忘了关听写，音频一直上传、一直计费。
- key 或它的片段出现在日志、菜单、进程参数或仓库里。
- 结束听写时键盘卡住，或热键失灵。

## 实测得到的约束

全部来自同一段 30 秒中英德混说录音（及其插入 15 秒静音的版本），对
`wss://api.openai.com/v1/realtime?intent=transcription` 用一次性测试工具回放得到。
数字是这段录音上的观察值，不是保证；延迟是对照另一个模型给的词时间戳估的，没有人工校准。

协议（两位审核者对照官方文档确认）：

- 官方 key 可用 `gpt-live-transcribe`，提交之前就返回增量文字。
- 音频必须是 24 kHz 16 位单声道 PCM；16 kHz 被拒绝。
- `turn_detection` 必须为 `null`；连接刚建立时服务端的默认配置不是这样，必须等 `session.updated`。
- 增量只追加：所有已提交片段里，增量拼起来和最终稿去掉首尾空格后完全相同。
  官方文档提示后续增量可能修正前文，所以仍要规定不一致时怎么办。
- 建连加配置 0.7–1.4 秒；会话有效期 60 分钟；公布价 0.017 美元/分钟。

延迟与准确度：

- 文字落后语音的平均值：`minimal` 约 0.25 秒，`low` 约 0.65 秒，`medium`（不设）约 0.9 秒，
  `high` 约 1.25 秒，`xhigh` 约 1.35 秒。单个词最慢到过 1.0 秒（`low`）和 1.9 秒（`high`）。
- 出厂默认组合（`low`、不设语言、无词表）两次都把德语术语认错。
- `low` 加语言列表和词表：句内音频不改动的 5 次里对了 4 次；`high` 加语言列表、无词表连续上传 2 次全对。
- 模型在汉字和拉丁词之间加不加空格不固定（`一个 PR解决`、`一个PR解决`、`的position` 都出现过）。

静音处理：

- 使用者环境底噪约 −42 dBFS，高于现有固定阈值（约 −54 dBFS），固定阈值一次都没触发。
- 在停顿处提交会明显降低准确度（每段失去上下文），600、1000、1500 毫秒三种停顿长度都如此。
- 改动一句话内部的静音也会降低准确度：静音满 600 毫秒就截掉 1 次错 1 次，
  把停顿换成数字静音 3 次全错，其中一次还丢了一个汉字。
- 只在长停顿后暂停上传、不提交：停顿前的字在暂停前出完，恢复后不丢字（各 1 次）。
- 连续上传 15 秒纯环境噪声，没有凭空出字。

## 方案

| | 出字时机 | 结论 |
|---|---|---|
| A. 流式（`gpt-live-transcribe`） | 边说边出 | **选定**（使用者选择，实测和审核都支持） |
| B. 分段上传（`gpt-4o-transcribe`） | 停顿后才出 | 不满足流式要求 |
| C. A 打草稿，停顿后用 B 替换整句 | 边说边出，之后校正 | 要回删重打，费用翻倍，不需要 |

## 设计

### 1. 模块划分

| 文件 | 内容 | 语言 |
|---|---|---|
| `voxtral_dictation.c/.h`（新） | 静音闸门、文字拼接、配置解析。不碰网络，可离线测试 | 标准 C |
| `voxtral_openai.m/.h`（新） | WebSocket 会话、待发队列、提交、错误归类 | Objective-C |
| `voxtral_mic_macos.c` / `voxtral_mic.h` | 增加 `vox_mic_start_rate(int rate)`；`vox_mic_start()` 仍是 16 kHz | C |
| `voxtral_daemon.m` | 选后端、API 模式的音频线程、非阻塞结束、时长上限、菜单和提示 | Objective-C |

API 模式下麦克风直接按 24 kHz 采集，不做重采样。

### 2. 选后端（启动时决定一次，改了要重启）

- 默认本地模式。只有 `~/.config/voxtral/config` 里写了 `backend = openai` 才走 API 模式。
  环境里有 `OPENAI_API_KEY` 不会改变后端。
- API 模式：不需要模型目录，不初始化 Metal，不加载模型。
  key 先读环境变量 `OPENAI_API_KEY`，没有则读 `~/.config/voxtral/openai_key`。
- 启动失败要看得见：API 模式缺 key、key 文件权限不是 600、配置无效，或本地模式找不到模型时，
  弹出系统对话框说明原因再退出（现在本地模式缺模型是直接退出，双击 `.app` 时毫无反应）。
- 菜单顺序：当前模式（只读）、错误原因（没有错误时隐藏）、开始/停止、退出。
- `voxtral-daemon --check` 只检查配置和 key（本地模式则是模型目录），打印结果后退出，从不弹窗。
  改完配置可以用它自查，启动检查也靠它做自动测试。

### 3. 配置文件 `~/.config/voxtral/config`

```
backend = openai
languages = zh,en,de
delay = low
keywords = Leistungsverzeichnis, Einzelpreis, Gesamtpreis
max_minutes = 10
```

- 格式：每行 `名称 = 值`；`#` 到行尾是注释；逗号分隔的各项去掉首尾空白，空项丢弃；空值等于没写。
  不认识的名称、过长的值都算配置无效，不做截断。`max_minutes` 取 1–55 的整数（会话 60 分钟过期，留出收尾时间）。
- `backend` 只在启动时读。`languages`、`delay`、`keywords`、`max_minutes` 每次按 ⌥Space 开始时重新读。
- 默认值：`delay = low`，`max_minutes = 10`，不设语言，无词表。
  要混说德语术语必须配置 `languages` 和 `keywords`（实测不配会认错），README 里写明。
- `delay` 不是五个合法值之一、词条含换行或 `<>`、`languages` 的某项含 ASCII 字母、数字和 `-` 以外的字符
  （例如中文输入法打出的全角逗号 `zh，en`）时：本次听写不开始，菜单显示"配置无效"及原因。

### 4. 一次听写

每次听写有一个递增的编号。听写的状态只在主队列上读写；网络回调在一个串行队列上执行，
带着编号回到主队列，编号不是当前这次的一律丢弃（防止上一次的字打进新窗口）。

**开始**：读配置，响提示音，按 24 kHz 开麦克风，同时建连。音频线程从开麦起持续读麦克风并交给新模块，
不走本地模式的积压丢弃和旧静音逻辑。收到 `session.updated` 之前不发任何音频，先放进待发队列
（上限 10 秒，超出则以"网络太慢"结束本次听写）。建连期间再按 ⌥Space：还没检测到说话就直接取消，
不提交，不报错；已经说了话则照常收尾，但提交必须在按键后 5 秒内发出（以发送完成为准，不是交给发送队列），否则按"网络"出错处理。

**进行中的静音闸门**（每 10 毫秒一帧）：

- 底噪：音量低于 0.001 的帧（数字静音）不参与估计。初值取第一个参与估计的帧，之后遇到更安静的帧立刻下调，
  否则每秒上浮约 0.9 dB。还没有初值时按 0.001 算。
- 有声：音量高于"底噪 × 2"，且高于 0.002。
- 连续静音满"尾随时间"后暂停上传：`minimal`/`low`/`medium` 为 1.5 秒，`high`/`xhigh` 为 2.5 秒。
  尾随期间上传的是真实音频（使用者同意；换成数字静音实测会降低准确度）。
- 重新有声时先补发之前 300 毫秒的真实音频，再继续（使用者同意）。
- 停顿处不提交，整次听写是同一段。
- 已知取舍：比底噪高不到一倍的轻声会被漏掉；短于尾随时间的停顿不省上传量。

**文字**：

- 按 `item_id` 累积收到的增量，收到就打，只追加，绝不退格。一次听写开头的空白不打。
- 收到最终稿时：如果它比已打出的内容多出一段后缀，补打这段后缀；其他不一致一律保留已打出的文字。
- 补空格：记住本次听写打出的最后一个字符（跨增量），汉字与拉丁字母或数字相邻而中间没有空格时补一个，
  两个方向都补。拉丁字母包含 `ä ö ü ß` 等（U+00C0–U+024F）。

**结束**（⌥Space、到达时长上限、出错三者都走同一个入口，重复调用无副作用）：

1. 状态改为"收尾中"，这期间忽略热键。主线程不等待任何东西。
2. 后台：停止采集，把麦克风里剩下的音频和不满一包的音频发完；本段累计上传满 100 毫秒才发提交，
   否则直接关连接。
3. 等最终稿，最多 2 秒，从提交真正发出（发送完成）时算起，上行慢时不会因为提交还在排队而提前超时。
   超时则菜单显示"结尾可能不完整"。
4. 收尾的字全部在主队列打完之后，才响结束音、回到空闲。
5. 关连接并销毁会话对象（`invalidateAndCancel`）。
6. 向 stderr 打印一行 `voxtral-daemon: uploaded X.X s of Y.Y s captured`：Y 是交给会话的音频时长，
   X 是其中上传的时长。这一行只有这两个数，用来核对静音时确实暂停了上传。

**时长上限**：单次听写最长 `max_minutes` 分钟，从开始算，与有没有文字无关。到点自动结束，
响一声和正常结束不同的提示音，菜单里注明已到上限，
要继续就再按一次（使用者同意，默认 10 分钟）。到点后收尾时出错的，照出错处理（错误音、⚠️），
菜单显示"已到 N 分钟上限，自动结束；"后接和平时一样的出错原因（例如"已到 10 分钟上限，自动结束；出错：网络"）。
有了它，第 1 版的"2 分钟无新文字自动结束"删除：
那个计时在嘈杂环境里永远不触发，在安静环境里又没必要。

### 5. 出错时

连不上、key 无效、中途断线、待发队列超限：走上面的结束流程（不提交），响错误音，图标变 ⚠️，
下次开始听写时恢复。菜单只显示固定的几种原因（网络、key 无效、配置无效、服务端拒绝、超时），
不显示服务端返回的原文，日志同理（服务端的报错会回显 key 的头尾片段）。
建连握手时服务端返回 401 算"key 无效"，返回其他 HTTP 状态码（403、429、5xx 等）算"服务端拒绝"，
没有收到 HTTP 响应算"网络"。不自动回退到本地模型。

会话用 `ephemeralSessionConfiguration`，不落盘缓存。

### 6. 顺带修复

`voxtral_daemon.m` 现有的热键监听被系统超时禁用后无法恢复：创建时 `refcon` 传的是 `NULL`，
重新启用的那行代码因此不起作用。把监听句柄存成静态变量即可。本地模式结束听写时仍会阻塞主线程，不在本次范围。

### 7. 测试

- `make test-dictation`（离线，不需要 key 和模型，几秒）：
  - 静音闸门：全零帧之后能恢复、尾随和补发的边界、轻声、持续噪声、两种尾随时间。
  - 文字拼接：跨增量补空格（含变音字母）、最终稿多出后缀、最终稿不一致、空最终稿。
  - 配置解析：注释、空白、空项、非法值。
- `make test-api`（联网，没有 key 时跳过并明说）：`samples/jfk.wav` 离线转成 24 kHz 后按实时速度送入，
  检查提交之前至少收到一段文字，且结果包含 "ask not what your country can do for you"。
- `make test-daemon`：用 `--check` 验证各种启动情况（配置无效、缺 key、key 权限不对、缺模型、
  环境里有 key 但没开启 API 模式时仍是本地模式）。
- `make test` 先跑 `test-dictation`，再跑现有回归。
- 手动：快速连按热键、建连中取消、拔网线、双击 `.app` 的各种启动失败、对着编辑器混说。

## 留给实现者

- 单段不提交的音频最长能到多少未知。按 `max_minutes` 的默认值实跑一次确认；不行就调低默认值。
- 静音闸门的"× 2"和尾随时间只在一段录音、一个环境里验证过，实现后用真实麦克风再调。
- 各档位的延迟要用真实麦克风量一次"说完到屏幕出字"的时间，测试工具量的不是这个。
- `voxtral_openai.m` 内部的锁：回调一律在锁外派发。
